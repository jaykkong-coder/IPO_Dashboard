# 상장일 물량구조 재정의 설계 (의무보유확약 · 유통가능주식수)

작성일: 2026-07-28
상태: 승인됨 (설계)
대상 범위: non-SPAC 신규상장 955사 (2016-01-22 ~ 2026-07-06)

## 1. 배경

`ipo_scatter_pack.pdf` / `ipo_performance_report.pdf` 의 두 핵심 변수인 **의무보유확약비율**과
**유통가능주식수비율**을 검증한 결과, 두 변수 모두 정의 단계에서 결함이 있음이 확인되었다.
값을 고치는 것으로는 해결되지 않으며 정의 자체를 다시 세워야 한다.

### 1.1 확인된 결함

**의무보유확약비율** (출처: 38커뮤니케이션, `scraper_38.py`)

| 결함 | 증거 |
|---|---|
| 정의 불일치 — 38은 수요예측 **신청수량** 기준, DART는 **배정수량** 기준 | 마키나락스 38값 78.17% vs DART 배정기준 98.2% / 토모큐브 0.14% vs 1.19% |
| 괴리 배율이 건별로 불규칙 → 단조변환이 아니므로 순위상관도 왜곡 | 배율 1.26배 ~ 8.5배 ~ 무한대 |
| `0.0%` 가 실제 0이 아님 | 38 리스트가 `-`(미보유)로 표기한 건을 상세페이지가 `0.00%` 로 렌더 → 파서가 실측값으로 저장. 에이치브이엠 DB 0.0% vs DART 실제 27.13% |
| 레짐 브레이크 | 분기 중앙값 2025Q3 8.1% → 2025Q4 52.8% → 2026Q1 63.9% (확약 우선배정 제도 변경). 시계열 절대수준 비교 불가 |

영향 건수: `0.0` 기록 81건(non-SPAC), 그중 현행 분석 유니버스 6건.

**유통가능주식수비율** (출처: DART 투자설명서, `ipo_extractor.py::_extract_float`)

투자설명서의 유통가능물량 표는 **공모 전에 작성**되므로 수요예측 후 확정되는 기관 확약을
구조적으로 반영할 수 없다. 따라서 이 값은 항상 과대계상이며, **과대 폭이 확약률에 비례**한다.

| 회사 | 투설 유통비율 | 확약 물량 | 확약 %p | 실제 유통비율 | 과대계상 |
|---|---|---|---|---|---|
| 마키나락스 | 38.48% | 1,597,511주 | 8.75%p | 29.73% | +8.75%p |
| 에이치브이엠 | 32.04% | 477,130주 | 3.89%p | 28.15% | +3.89%p |
| 토모큐브 | 32.17% | 17,829주 | 0.13%p | 32.04% | +0.13%p |

추가로 2016~2023 구간은 미검증 상태이며 100% 초과값이 7건 존재한다
(알체라 871%, 블루엠텍 793%, 삼성바이오로직스 574%, LG에너지솔루션 193% 등).

### 1.2 근본 원인

두 변수를 **독립 변수로 따로 수집**한 것이 원인이다. 실제로는 하나의 물량 항등식을 구성하는
조각이며, 따로 수집하면 서로의 측정오차가 상대 변수로 새어든다. 확약이 높은 딜일수록
유통비율이 더 부풀려지므로 **두 변수 사이에 인위적 음의 상관**이 발생한다.

이는 v1.1 결론 ③ "유통비율은 약한 역방향" 이 확약 효과의 누출일 가능성을 시사한다.

### 1.3 유효성이 확인된 사항

상장분기를 통제해 분기 내 편차로 재계산해도 확약↔초과수익률 상관은 유지된다
(1M +0.58→+0.51, 3M +0.42→+0.45, 6M +0.26→+0.28, 12M +0.35→+0.32).
따라서 "확약이 최강 요인" 이라는 결론은 시점 교락이 아니며, 정의 교체 후에도 유지될 전망이다.
다만 신청기준→배정기준 전환으로 계수는 달라진다.

## 2. 지표 정의

```
상장예정주식수(공모후)
  = A 기존주주 보호예수
  + B 기관 의무보유확약
  + C 우리사주조합
  + D 실유통물량
                          A + B + C + D = 총 (항등식, 검증에 사용)
```

| 기호 | 명칭 | 정의 |
|---|---|---|
| A | 기존주주 보호예수 | 최대주주·특수관계인·VC·전략투자자 등의 상장 시점 의무보유 물량 |
| B | 기관 의무보유확약 | 수요예측 배정 기관투자자 중 확약분 = 기관배정 − 미확약 |
| C | 우리사주조합 | 1년 의무예탁 물량 |
| D | 실유통물량 | 상장일 매도 가능 물량 |

**주지표: `free_float_pct = D / 총`** — 상장일 실유통비율.
**보조지표: `lockup_inst_pct = B / 기관배정`** — 배정기준 확약률.

기존 38 신청기준 확약률은 별도 컬럼으로 공존시키며 폐기하지 않는다. 두 지표는 의미가 다르다.

### 2.1 범위 결정

본 설계는 **상장일 스냅샷**만 다룬다. 확약기간별(15일/1개월/3개월/6개월) 해제 스케줄은
DART 원문에 존재하므로 수집은 하되, 시점별 유통물량 곡선 산출은 별도 프로젝트로 분리한다.

## 3. 데이터 소스

| 항목 | 소스 | 획득 방법 |
|---|---|---|
| B 확약, C 우리사주, 기관배정 | DART 증권발행실적보고서 | OpenDART `list.json` → `document.xml`, 「기관투자자 의무보유확약기간별 배정현황」 및 「청약 및 배정현황」 표 파싱 |
| A 보호예수, 총주식수 | DART 투자설명서 | 로컬 캐시 `docs/<회사명>/<rcept_no>.xml` 769사 + 신규 다운로드 186사. **1순위 `verify_float_extractor.py`(규칙 기반), 2순위 Haiku fallback** — §3.2 참조 |
| D 실유통 | 위 두 소스 | 투설 파싱값과 항등식 역산값을 **양쪽 산출 후 대조** |

### 3.2 A 추출 전략 — 기존 자산 재사용 우선

설계 시점에는 A 추출을 Haiku 전량 처리로 가정했으나, 코드베이스 조사 결과
**`verify_float_extractor.py`(433줄)가 이미 같은 문제를 규칙 기반으로 해결**해 두었다.
2026-07-28 재실행 실측치:

```
캘리브레이션 결과: 160/172 일치 (93.0%)
confident인데 틀린 건(위험): 0건
```

핵심 특성은 정확도 93%가 아니라 **wrong-confident가 0건**이라는 점이다.
이 추출기는 확신할 때만 값을 내고 애매하면 `ambiguous` 로 빠지므로,
`confident` 판정은 추가 검증 없이 자동 승인해도 안전하다.

따라서 A 추출은 2단 구조로 간다.

| 단계 | 처리 | 대상 |
|---|---|---|
| 1순위 | `verify_float_extractor.extract_for_company()` | 전체. `confident` → 자동 채택 |
| 2순위 | Haiku 4.5 구조화 추출 | 1순위가 `ambiguous` / `no_cached_doc` 인 건만 |

Haiku 호출량이 955건에서 잔여분(추정 100건 내외)으로 줄어든다.
955건 전량을 LLM으로 돌린 뒤 검증하는 것보다 비용·시간·리스크가 모두 낮다.

**주의: `ANTHROPIC_API_KEY` 가 현재 환경에 설정되어 있지 않다.** 2순위 단계 착수 전 설정이 필요하다.
미설정 상태에서는 1순위만 실행하고 잔여분을 `verdict='failed'` 로 남긴 뒤 나중에 채운다.

### 3.1 소스 실현가능성 (표본 검증 완료)

- 2018~2026: 증권발행실적보고서에 확약표 + 우리사주 배정 안정적으로 존재
- 2016~2017: 표본 8건 중 5건 확보. 미확보분은 대부분 코넥스 이전상장 등 **공모가 없어 확약 개념이 성립하지 않는** 건으로, 결측이 아니라 N/A로 분류
- 구형 문서는 **EUC-KR** 인코딩 → `utf-8 → cp949` 순차 디코드 필요
- 확약표 컬럼 구조가 시기별로 상이 → 투자자 유형별 열이 아닌 **"합계" 열**을 고정 참조

## 4. 스키마

기존 `ipo_companies` 컬럼은 수정하지 않는다. 신규 테이블에 적재해 롤백 가능성과
신·구 값 대조 가능성을 확보한다.

```sql
CREATE TABLE IF NOT EXISTS share_structure(
    corp_code        TEXT PRIMARY KEY,
    listing_date     TEXT,
    total_shares     INTEGER,   -- 공모후 상장예정주식수
    lockup_existing  INTEGER,   -- A 기존주주 보호예수
    lockup_inst      INTEGER,   -- B 기관 확약
    esop             INTEGER,   -- C 우리사주조합
    free_float       INTEGER,   -- D 실유통 (투설 파싱 기준)
    free_float_pct   REAL,      -- 주지표 D/총 ×100
    inst_alloc       INTEGER,   -- 기관 총배정
    lockup_inst_pct  REAL,      -- 보조지표 B/기관배정 ×100
    lockup_15d       INTEGER,   -- 확약기간별 (스케줄 확장 대비)
    lockup_1m        INTEGER,
    lockup_3m        INTEGER,
    lockup_6m        INTEGER,
    identity_gap     REAL,      -- 항등식 오차 %p
    verdict          TEXT,      -- auto_ok | manual_ok | failed | na
    src_impl_rcept   TEXT,      -- 증권발행실적보고서 접수번호
    src_prosp_rcept  TEXT,      -- 투자설명서 접수번호
    evidence         TEXT,      -- 추출 근거행
    updated_at       TEXT
);
```

`verdict = 'na'` 는 공모 없는 상장(이전상장 등)으로 확약 개념이 성립하지 않는 건에 사용한다.
결측(`failed`)과 구분해야 분석에서 잘못 제외하거나 포함하는 사고를 막을 수 있다.

## 5. 검증 게이트

수작업 검증량을 최소화하기 위해 4중 자동 게이트를 둔다.

```
① 부호     A ≥ 0,  B ≥ 0,  D ≥ 0
② 범위     D/총 ∈ [3%, 85%]
③ 확약     B ≤ 기관배정,  B = 15d+1m+3m+6m 합과 일치
④ 38 대조  38 신청기준 확약률 ≤ 배정기준 확약률 + 1.0%p
     ↓
전부 통과 → verdict='auto_ok'
하나라도 실패 → verdict='failed' → 수작업 큐
```

**항등식 자체는 게이트가 될 수 없다.** A를 `총 − 투설유통 − C` 로 역산하므로
`A+B+C+D = 총` 이 대수적으로 항상 성립한다. `identity_gap` 은 언제나 0이며 검증력이 없다.
컬럼은 훗날 A를 독립 추출하게 될 때를 위해 남기되 게이트에서는 제외한다.

따라서 **④가 유일한 외부 교차검증**이다. 38커뮤니케이션과 DART는 완전히 독립된 소스이고,
확약기관 우선배정 구조상 신청기준이 배정기준을 넘을 수 없다. 부등식이 깨지면 둘 중 하나가 틀렸다.
①②③은 내부 정합성 검사로, 파서가 엉뚱한 열·행을 잡은 경우를 걸러낸다.

### 5.1 골든셋 캘리브레이션 (본 수집 선행 조건)

`data_corrections` 테이블의 168건(사람 검증 완료: ok 119 + corrected 49)을 정답셋으로 사용한다.

**주의: 골든셋의 `verified_value` 는 "투설 기준 유통가능비율"이지 보호예수 값이 아니다.**
따라서 A를 직접 대조할 수 없고, 아래 관계를 경유해 검증한다.

```
투설 유통가능물량 = 총주식수 − A(보호예수) − C(우리사주)
  ⟹ Haiku 추출값으로 재구성한 (총 − A − C)/총  ==  골든셋 verified_value
```

즉 Haiku가 A와 총주식수를 정확히 뽑았다면 위 재구성값이 골든셋과 일치해야 한다.
불일치는 A 또는 총주식수 추출 실패를 뜻한다.

`verify_float_extractor.run_calibration()` 이 이미 이 대조를 수행한다(2026-07-28 실측 160/172, wrong-confident 0).

**합격 기준은 커버리지가 아니라 wrong-confident 건수다.**

| 기준 | 임계값 | 근거 |
|---|---|---|
| wrong-confident (틀렸는데 confident) | **0건 (필수)** | 자동 승인 경로에 오염이 들어가는 유일한 통로. 1건도 허용 불가 |
| confident 커버리지 | ≥ 85% (권장) | 미달해도 진행 가능. 잔여는 Haiku fallback 또는 수작업으로 흡수 |

커버리지가 낮으면 사람 손이 더 들 뿐이지만, wrong-confident는 조용히 틀린 데이터를 만든다.
전자는 비용 문제이고 후자는 신뢰 문제이므로 기준을 다르게 둔다.

1. 1순위 추출기: 위 기준으로 이미 합격 (wrong-confident 0)
2. Haiku fallback: 골든셋 중 1순위가 `ambiguous` 판정한 건을 대상으로 동일 기준 적용.
   **wrong-confident가 1건이라도 나오면 fallback을 쓰지 않고 해당 건을 수작업 큐로 보낸다**
3. 두 경로 모두 실패한 건은 `verdict='failed'` 로 남기고 절대 추정값을 채우지 않는다

### 5.2 우리사주 포함 여부 확정

투자설명서 유통가능물량 표가 우리사주(C)를 유통제한에 포함하는지는 회사마다 다를 수 있다.
포함 여부를 잘못 가정하면 A에 체계적 오차가 생기므로, Haiku 추출 시
**유통제한 물량의 내역별 구분(최대주주등 / 기관확약 / 우리사주 / 기타)을 행 단위로 함께 추출**한다.

- 우리사주가 별도 행으로 존재 → 그 값을 C 검증에 사용하고 A에서 제외
- 존재하지 않음 → C는 DART 증권발행실적보고서 값을 사용하고, 항등식 ①이 이중계상을 검출

또한 표에 "기관확약" 행이 이미 존재하는 케이스(발행조건확정 후 정정 투설)가 있을 수 있다.
이 경우 B를 이중계상하게 되므로, 해당 행이 검출되면 투설 값이 아닌 DART 값을 B로 채택한다.

```
rebuild_reports.py        scatter pack / performance report 재생성
```

각 스크립트는 독립 실행 가능하며 중간 산출물을 DB에 남긴다. 재실행 시 이미 처리된 건은 건너뛴다
(DART 일일 20,000건 한도 및 재시도 비용 고려).
